Programming ATtiny85 with Arduino Uno

A practical, exam-ready guide to using an Arduino Uno as an ISP programmer, wiring an ATtiny85, uploading a small embedded sketch, and checking the result safely.

1. Introduction and learning objectives

ATtiny85 is a small 8-bit AVR microcontroller from the ATtiny family. It can run a program stored in its flash memory and control digital inputs/outputs, timers, and other on-chip peripherals. An Arduino Uno can be used as an in-system programmer (ISP) to transfer a compiled program to the ATtiny85 through its SPI programming interface.

By the end, you can…Identify the programmer, target MCU, power, ground, reset, and SPI signal connections.
Build & uploadPrepare the Uno as ISP, select the correct ATtiny target/clock, burn bootloader settings if required, and upload using programmer.
Test & debugUse a simple LED test and diagnose wiring, board-package, clock, and programmer errors.

Why it matters

Programming a small MCU is useful for compact sensor nodes, simple controllers, wearables, battery-powered prototypes, and low-cost embedded products. The ATtiny85 is valuable when a full-size development board is unnecessary, although its limited memory, I/O, and peripherals must be considered.

Prerequisites

  • Digital logic basics: HIGH/LOW and digital pins.
  • Basic C/C++ syntax and Arduino functions such as pinMode(), digitalWrite(), and delay().
  • Power-supply polarity, common ground, and reading pinout diagrams.
  • Basic idea of a compiler, firmware, flash memory, SPI, and ISP.

2. System architecture and wiring diagram

The Uno runs the ArduinoISP sketch and acts as the programmer. The ATtiny85 is the target. The following is the common DIP-8 wiring for an ATtiny85 using the Uno's hardware SPI pins. Confirm the pinout and board-package instructions before powering the circuit.

Pin numbering: On a DIP package, locate the notch or pin-1 dot. Number pins counter-clockwise when viewed from the top. PB0/PB1/PB2 names also have alternate functions; their function depends on the selected configuration and current program.

3. Step-by-step programming procedure

  1. Prepare the Uno. Connect the Uno to the computer and open the Arduino IDE.
  2. Load ArduinoISP. In the IDE, open File → Examples → 11.ArduinoISP → ArduinoISP (menu grouping may vary), choose the correct Uno board and COM port, then upload the sketch to the Uno.
  3. Wire the target. With power disconnected, connect the six ISP signals and supply as in Figure 1. Check pin-1 orientation and common ground.
  4. Install/select the ATtiny board package. Use a reputable package compatible with your IDE. Select ATtiny85, the desired clock option, and the correct programmer option. Exact menus depend on the package.
  5. Set the clock configuration. Select a clock setting supported by your chip and intended circuit. If the package requires it, use Burn Bootloader to configure fuse bits/clock settings; for classic ATtiny85 ISP workflows this generally does not install a serial bootloader.
  6. Upload with programmer. Choose Sketch → Upload Using Programmer. Do not use the ordinary Upload button unless the selected workflow explicitly requires it.
  7. Verify the result. Disconnect programming wires if needed, then test the target with a known sketch and a suitable LED resistor or a multimeter/logic probe.
Uno reset note: Some Uno-based ArduinoISP setups need a capacitor (often around 10 µF electrolytic) between RESET and GND on the Uno after uploading ArduinoISP to prevent auto-reset during programming. Follow the ArduinoISP instructions for your Uno/IDE; observe electrolytic polarity and do not add it blindly to the target reset line.

Operating conditions and assumptions

  • Use a voltage compatible with the target's datasheet and selected clock. A 5 V Uno supply is common in a 5 V lab setup, but verify the exact ATtiny85 variant and operating frequency.
  • Keep wires short and connections secure; a breadboard is fine for low-speed ISP programming when wired correctly.
  • Do not short VCC to GND. Disconnect power before rewiring.
  • If the clock fuse was set to an external clock source and no clock is present, ISP communication may fail until a suitable clock is supplied and the configuration is recovered.

4. Example firmware: blink an LED

This is a minimal test sketch for the ATtiny85. It assumes the chosen board package maps Arduino pin number 0 to PB0 (DIP pin 5). Use an external LED with a current-limiting resistor, for example 330 Ω to 1 kΩ, and verify polarity. The delay is in milliseconds.

// ATtiny85 LED blink test
// Assumption: Arduino pin 0 maps to PB0 on the selected core.
const int LED_PIN = 0;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(500);
  digitalWrite(LED_PIN, LOW);
  delay(500);
}

Signal timing (illustrative)

Timing calculation

Period: T = tHIGH + tLOW = 0.5 s + 0.5 s = 1.0 s
Frequency: f = 1/T = 1/1.0 s = 1 Hz
Duty cycle: D = (tHIGH/T) × 100% = (0.5/1.0) × 100% = 50%

The output frequency is approximately 1 Hz when the delay timing is accurate. Actual timing can differ because of oscillator tolerance, core implementation, and delay calibration. delay() timing depends on the configured clock.

5. Equations and solved numerical examples

This is a programming topic, so the most useful calculations are timing, duty cycle, and safe LED current limiting—not analog gain or frequency-response equations.

Equation sheet

Period: T = tHIGH + tLOW (seconds)
Frequency: f = 1/T (hertz)
Duty cycle: D = (tHIGH/T) × 100%
LED series resistor: R = (VSUPPLY − VF)/ILED (ohms), for a simple DC series circuit

In the resistor equation, VSUPPLY is supply voltage in volts, VF is LED forward voltage in volts, and ILED is desired LED current in amperes. It assumes a simple series path and ignores small output-driver voltage drop; check MCU pin current limits and datasheet ratings.

Solved example 1 — blink frequency

Given: LED stays HIGH for 250 ms and LOW for 250 ms. Find: period and frequency.

  1. Convert: 250 ms = 0.25 s.
  2. Period: T = 0.25 + 0.25 = 0.50 s.
  3. Frequency: f = 1/0.50 = 2 Hz.

Answer: T = 0.50 s, f = 2 Hz. The LED completes two full ON/OFF cycles each second.

Solved example 2 — LED resistor

Given: 5 V supply, LED forward voltage 2.0 V, desired current 5 mA. Find: series resistor.

  1. Convert current: 5 mA = 0.005 A.
  2. Voltage across resistor: 5 − 2 = 3 V.
  3. R = 3/0.005 = 600 Ω.
  4. Choose a common value at or above this estimate, such as 680 Ω, after checking brightness and datasheet current limits.

Answer: theoretical minimum estimate 600 Ω; a 680 Ω resistor gives about 4.4 mA under these ideal assumptions.

Solved example 3 — GATE-style duty cycle

Given: an output has T = 4 ms and stays HIGH for 1 ms. Find: frequency and duty cycle.

  1. Frequency: f = 1/(4 × 10−3 s) = 250 Hz.
  2. Duty cycle: D = (1/4) × 100% = 25%.

Answer: 250 Hz and 25%. Remember to convert milliseconds to seconds when calculating frequency in hertz.

7. GATE-style practice — 10 original questions

These are original practice questions, not claimed to be actual previous-year GATE questions. Expand each item to view the answer and reasoning.

Easy Q1. Which interface is commonly used by an Arduino Uno to ISP-program an ATtiny85?

Answer: SPI-based ISP. MOSI, MISO, and SCK carry serial programming data/clock, while RESET places the target in programming mode. UART serial bootloading is a different method.

Easy Q2. In the common DIP-8 pinout, which ATtiny85 pin is GND?

Answer: Pin 4. Pin 8 is VCC. Always confirm the package orientation before wiring.

Moderate Q3. A blink sketch uses 300 ms HIGH and 700 ms LOW. What are its period and frequency?

Answer: T = 1 s; f = 1 Hz. T = 0.3 + 0.7 = 1 s, so f = 1/T = 1 Hz.

Moderate Q4. For Q3, what is the duty cycle?

Answer: 30%. D = (0.3/1.0) × 100% = 30%.

Easy Q5. What is the main purpose of the ArduinoISP example?

Answer: It makes the Uno act as an in-system programmer for a supported target MCU. The sketch must first be uploaded to the Uno.

Moderate Q6. Why is a common ground needed between programmer and target?

Answer: It establishes a shared voltage reference and return path so logic levels can be interpreted reliably.

Moderate Q7. A 5 V source drives an LED with VF = 2 V at 6 mA. Estimate R.

Answer: 500 Ω. R = (5 − 2)/0.006 = 500 Ω. Choose a suitable standard value and check pin-current limits; 560 Ω is a conservative nearby choice.

Difficult Q8. After selecting an external-clock fuse setting, ISP communication fails. What is a plausible explanation?

Answer: The MCU may need an external clock to run its programming interface as configured. Supply a suitable clock to recover if appropriate, then restore a valid clock configuration. Exact recovery depends on fuse changes and hardware.

Moderate Q9. What is the difference between uploading ArduinoISP to the Uno and uploading a sketch to the ATtiny85?

Answer: The first programs the Uno with programmer firmware; the second uses that firmware to transfer the compiled target program through ISP.

Difficult Q10. A 1 kHz square wave has a 20% duty cycle. How long is the HIGH interval?

Answer: 0.2 ms (200 µs). T = 1/1000 = 1 ms; tHIGH = 0.20 × 1 ms = 0.2 ms.

8. Core electronics company interview preparation

Use these answers as a starting point; a strong candidate also explains the signal path and describes how they would verify it on hardware.

1. What is the ATtiny85?

An 8-bit AVR microcontroller with on-chip flash, SRAM, EEPROM, GPIO, timers, and other peripherals. Its small footprint suits compact control tasks, but memory and I/O resources are limited.

2. What does ISP mean, and why use it?

In-system programming lets firmware be written to a chip without removing it from the target circuit. It is useful during prototyping, production programming, and field/service workflows when the board exposes the required programming connections.

3. Explain MOSI, MISO, and SCK.

MOSI is data from programmer to target, MISO is data from target to programmer, and SCK is the serial clock. The target reset/programming control is also required for classic AVR ISP.

4. Why upload ArduinoISP before programming the ATtiny85?

The Uno needs firmware that implements the programmer protocol. Uploading ArduinoISP turns the Uno into the bridge between the IDE/programming tool and the target MCU.

5. Why might a device-signature error occur?

Possible causes include swapped SPI lines, missing common ground or power, wrong target selection, incorrect reset wiring, wrong port, or an Uno auto-reset issue. Verify the simplest electrical causes first.

6. What are fuse bits?

Non-volatile configuration bits that select MCU options such as clock source and startup behavior. Incorrect settings can prevent expected timing or make ordinary ISP recovery difficult.

7. Does “Burn Bootloader” necessarily install a serial bootloader?

No. In many ATtiny85 board-package workflows, the action primarily sets fuse/configuration values such as the clock. Confirm the behavior of the selected core and programmer.

8. How would you validate a blinking output?

Check supply and ground, confirm pin mapping, inspect LED polarity and series resistor, then measure the output with a multimeter, oscilloscope, or logic analyzer. Compare measured period/duty cycle with the configured delay and clock.

9. What changes when the clock setting changes?

CPU instruction timing and timer/peripheral timing change. Software delays and serial/peripheral baud rates may change unless their configuration accounts for the new clock. A mismatch can make observed timing inaccurate.

10. How would you make a small sensor node production-ready?

Verify voltage and current budgets, sleep/wake behavior, sensor interface timing, watchdog/fault recovery, EMC/noise, programming pads, test coverage, firmware versioning, and operation across temperature and supply ranges.

11. Can every Arduino library run on ATtiny85?

No. Libraries may depend on unsupported peripherals, timers, memory, pin mappings, or a particular MCU architecture. Check core compatibility, flash/SRAM use, and required hardware resources.

12. What is a practical limitation of using an Uno as ISP?

It is convenient for labs but adds wiring and setup steps, and it is not a substitute for a production programmer fixture when repeatability, throughput, traceability, or isolation are required.

Industry perspective

In an embedded hardware team, the same skills are used to bring up a new board, program firmware through test pads, verify GPIO and timing, and isolate hardware-versus-firmware faults. Production designs should document the connector/pad pinout, programmer settings, fuse configuration, firmware checksum/version, and pass/fail test procedure.

10. Applications, advantages, and limitations

Applications

  • Simple sensor polling and threshold alarms.
  • LED indicators, small user interfaces, and timing controllers.
  • Compact low-cost prototypes and educational embedded projects.
  • Small battery-powered products when sleep modes and power budget are designed carefully.

Advantages

  • Small package and relatively simple hardware.
  • In-system programming using common lab hardware.
  • Good for learning GPIO, timers, firmware compilation, and board bring-up.

Limitations

  • Limited memory, pins, and peripheral set.
  • Board-core and library compatibility must be checked.
  • Clock/fuse mistakes can complicate recovery.
  • Not a Wi-Fi/Bluetooth radio by itself; IoT connectivity requires additional hardware or a different MCU.

11. Quick revision sheet

High-priority facts

  • Arduino Uno = programmer; ATtiny85 = target MCU.
  • Classic DIP-8 ATtiny85: pin 1 RESET, pin 4 GND, pin 5 PB0/MOSI, pin 6 PB1/MISO, pin 7 PB2/SCK, pin 8 VCC.
  • Uno hardware SPI pins: D10 used for target RESET in the common ArduinoISP wiring; D11 MOSI; D12 MISO; D13 SCK.
  • Upload ArduinoISP to the Uno first, then use the target board selection and “Upload Using Programmer”.
  • Check the board package's clock setting and fuse behavior; menu wording varies.
  • For a square wave: frequency is reciprocal of period; duty cycle is HIGH time divided by total period.
  • Use an LED series resistor and keep MCU pin current within datasheet limits.

Common mistakes

  • Confusing the Uno's pins with the ATtiny85's physical pin numbers.
  • Forgetting common ground or reversing the DIP chip.
  • Using normal Upload instead of Upload Using Programmer in an ISP workflow.
  • Assuming every Arduino library/core feature is available on ATtiny85.
  • Assuming illustrative waveforms are real simulation measurements.
  • Changing fuse settings without understanding clock-source recovery.

Memory aid

“10 Reset, 11 MOSI, 12 MISO, 13 Clock” for the common Uno ISP wiring. On the target, remember the DIP-8 anchors: 1 Reset, 4 Ground, 8 VCC. Always confirm the package pinout before applying power.
